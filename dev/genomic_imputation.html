6  Imputed Genomics

This page provides considerations for A2CPS projects that involve the Imputed Genomics Data.

The imputed genomic dataset expands single-nucleotide resolution variant data across the human genome, offering deeper and more comprehensive coverage. Genotype imputation aligns SNP array data with ancestry-specific reference haplotypes to infer untyped variants with high confidence. This process can be compared to filling in missing letters in a sentence based on contextual knowledge — for example:

“T_e l_zy d_g j___ed _ver the _at.”

Imputation is particularly important in genetic association studies because it allows researchers to identify disease-associated loci that were not directly genotyped, facilitating meta-analyses across different studies that may have used different SNP arrays. For a deeper dive into the methodology and importance of imputation, see the TOPMed Imputation Server Documentation.

Following imputation in this dataset, the number of genetic loci increased from 690,126 to 11,016,319, spanning all 22 autosomes and the X chromosome for 1,375 participants. Prior to imputation, data were preprocessed and formatted for compatibility with the Imputation Server. Post-imputation, we applied rigorous quality control, excluding low-confidence variants and those with a minor allele frequency (MAF) below 1%.

6.1 Starting Project

6.1.1 Locate Data

We assume that the data were downloaded from the NIMH Data Archive (NDA) as a Data Package and saved to data/nda inside the project folder (Appendix C describes what a package contains). Each NDA data structure is a table, <structure>.txt, and any files that the structure references are underneath a folder of the same name, <structure>/. Paths in the text start from the folder that holds the structure’s files (for the MRI data, <structure>/corral-secure/projects/A2CPS/products/consortium-data/pre-surgery), while code chunks spell out the full path from the project folder.

The imputed genotypes are distributed with the genetic variant data (Chapter 5), which are referenced by the genomics_sample03 structure. That structure’s table holds sample-level information about the genotyping, and subject-level information is in the genomics_subject02 table. The files are underneath genomics_sample03/submission-85830:

$ tree data/nda/genomics_sample03
data/nda/genomics_sample03
└── submission-85830
    ├── GV_Genotypes_Runlists_1-5_QC_freeze2.bed
    ├── GV_Genotypes_Runlists_1-5_QC_freeze2.bim
    ├── GV_Genotypes_Runlists_1-5_QC_freeze2.fam
    └── GV_Genotypes_Runlists_1-5_QC_freeze2.vcf.gz

The .bed, .bim, and .fam files are a PLINK binary file set, and the .vcf.gz file is in the Variant Call Format.

6.1.2 Extract Data

To access the variant data efficiently, you should use plink2 (or plink 1.9). Plink can rapidly subset massive genomic datasets to pull only the specific variants or participants you need for an analysis. For more detail on Plink Binary File information and data extraction for genetic variant data, refer to the Genetic Variant starter kit.

6.2 Considerations while working with these data

6.2.1 Population Structure

Even after rigorous QC, population structure still exists within the dataset. Systematic differences in ancestry between groups can lead to spurious associations in genetic analyses. You should generally include genetic principal components as covariates in any downstream analyses (e.g., Polygenic Risk Scores or Genome-Wide Association Studies).

6.2.2 Custom Filtering

Researchers can choose to filter out variants based on other, standard QC measures that suit their specific study designs. The data provided here represents a strong baseline, but it may require additional tailoring depending on your research question.

6.2.3.3 Post-Imputation Quality Control

  • Imputed variants with an imputation quality score (R²) less than 0.3 were excluded.
  • Imputed variants with minor allele frequencies (MAF) below 0.01 were excluded to remove extremely rare variants.
  • Imputed variants lacking rsIDs (denoted as ‘.’) or sharing duplicated genomic positions were excluded, as these caused issues during PLINK merging.

# 4. UPDATE SEXES

# 5. Keep variants with (MAF > 0.01 and R2 > 0.3)

Click to show Supplementary RScript #1: Variant-Level QC Based on Quality Metrics(post_imputation_qc.R 
library(data.table)

setwd("./Imputation_Results/")

chromosomes <- c(1:22, "X")
for (chr in chromosomes) {
  folder <- paste0("chr_", chr)
  file_path <- file.path(folder, paste0("chr", chr, ".info.gz"))

  dose <- fread(file_path)

  dose[,
    c("AF", "MAF", "AVG_CS", "R2") := {
      af <- sub(".*AF=([^;]*).*", "\\1", INFO)
      maf <- sub(".*MAF=([^;]*).*", "\\1", INFO)
      avg_cs <- sub(".*AVG_CS=([^;]*).*", "\\1", INFO)
      r2 <- sub(".*R2=([^;]*).*", "\\1", INFO)
      list(as.numeric(af), as.numeric(maf), as.numeric(avg_cs), as.numeric(r2))
    }
  ]

  common <- dose[MAF > 0.01]
  well_imputed <- common[R2 > 0.3]
  setnames(well_imputed, "#CHROM", "CHROM", skip_absent = TRUE)
  well_imputed[, chr := sub("^chr", "", CHROM)]
  well_imputed[, start := POS]
  well_imputed[, end := POS]

  keep_ranges <- well_imputed[, .(chr, start, end)]

  fwrite(
    keep_ranges,
    file.path(folder, "keep_ranges.txt"),
    sep = "\t",
    col.names = FALSE,
    quote = FALSE
  )
}
